# md2wechat Electron 桌面端迁移设计

## 背景

md2wechat 当前将 React 前端嵌入 Go 二进制，通过本地 HTTP 服务在浏览器中运行。这个形态已经能做到单文件分发，但每次使用仍要先启动服务，窗口、目录选择和退出方式也不像桌面软件。

项目主要供本地个人使用。迁移后的应用需要在 Windows、macOS 和 Linux 上提供一致的独立窗口，关闭窗口后直接退出，不保留浏览器模式或后台托盘进程。

## 目标

- 使用 Electron 承载现有 React + Vite 界面。
- 不再启动 localhost 服务或 Go 子进程。
- 通过系统目录选择器打开一个 Markdown 文章库。
- 自动恢复上次打开的目录，并提供最近目录入口。
- 保留文章树、编辑预览、自动保存、磁盘变更检测和公众号富文本复制。
- 支持任意深度的目录，不再限制为两层。
- 使用 Electron 自带的 Chromium，减少三个平台之间的排版和剪贴板差异。

## 不在本次范围内

- 浏览器访问模式。
- 多窗口或同时打开多个文章库。
- 系统托盘和后台常驻。
- 自动更新、应用商店发布、代码签名。
- 非 Markdown 文件的编辑或预览。
- 第一阶段删除 Go 源码和现有发布工具。
- 新增自动化测试。实现完成后运行现有检查，并做桌面端手动验收。

## 技术选择

桌面端使用 Electron，不使用 Wails 或 Tauri。项目的核心功能是公众号排版预览和富文本复制。Electron 在三个目标平台上随应用分发 Chromium，可以让 DOM、CSS 和剪贴板实现保持在同一条技术线上。安装包和运行内存会增加，但个人本地工具不把包体作为主要约束。

应用使用 Electron Forge 打包。React 和 Vite 继续作为渲染进程的前端技术，不替换编辑器或 Markdown 渲染链路。

## 总体架构

```text
Electron Main
├─ 窗口、菜单和生命周期
├─ 原生目录选择器
├─ 应用配置
├─ 文章库文件操作
└─ IPC 处理
        │
        │ 受限、类型明确的接口
        ▼
Preload
└─ window.md2wechat
        │
        ▼
React Renderer
├─ 文章树
├─ Markdown 编辑器
├─ 公众号预览
└─ 保存、冲突和错误状态
```

主进程拥有文件系统权限。渲染进程不启用 Node.js 集成，只能调用预加载脚本明确暴露的方法。现有 `/api` HTTP 请求替换为 Electron IPC 调用。

## 组件边界

### 主进程

主进程创建单个应用窗口，注册系统菜单，处理目录选择、窗口关闭和应用退出。窗口关闭后进程直接结束，不创建托盘图标。

窗口禁止渲染进程访问 Node.js，开启上下文隔离和沙箱。应用拒绝未声明的页面跳转、新窗口和外部内容加载。

### 应用配置

配置保存在 `app.getPath('userData')` 对应的系统用户目录中，使用 Node.js 内置文件 API 读写 JSON，不额外引入配置存储依赖。配置只包含上次打开的文章库绝对路径，以及最近打开的 5 个文章库路径。最近目录按使用时间排序。

主题和左侧文章库折叠状态仍由现有前端状态管理。上次选中的文章也保存在前端，但改为按文章库根目录分别记录，避免两个文章库中相同的相对路径互相干扰。

配置文件不存在或内容损坏时，应用使用空配置启动。无效的最近目录会在访问失败后从列表中移除。

### 文章存储

文章存储迁移为主进程中的 TypeScript 模块，保持现有名称校验、同名冲突、`.md` 后缀和错误提示。所有调用都以当前文章库根目录为边界，渲染进程只能提交使用 `/` 分隔的相对路径。

文章树递归读取任意深度目录。目录项继续按目录优先、名称升序排列，只显示普通 `.md` 文件。符号链接不参与扫描，也不能通过文章操作访问。

创建目录不再检查深度。创建、读取、保存、重命名和删除都在主进程中校验路径，拒绝绝对路径、空路径段、`.`、`..`、反斜杠和空字符。访问已有路径时逐段检查文件类型并拒绝符号链接；创建新路径时先验证父目录，最终解析结果必须位于文章库根目录内。

目录删除保持现有语义，只允许删除不含文章和其他文件的空目录树。文章库根目录不能重命名或删除。

### 预加载脚本和 IPC

预加载脚本通过 `contextBridge` 暴露 `window.md2wechat`，不直接暴露 `ipcRenderer`。渲染进程使用下面的接口：

| 接口 | 输入 | 返回 |
| --- | --- | --- |
| `app.getBootstrapState` | 无 | 当前根目录、最近目录、文章树和启动错误 |
| `app.onBeforeClose` | 保存回调 | 取消订阅函数 |
| `app.resolveClose` | `saved`、`continue-editing` 或 `discard` | 无 |
| `library.choose` | 无 | 取消时返回 `null`，成功时返回根目录和文章树 |
| `library.open` | 最近目录的绝对路径 | 根目录和文章树 |
| `library.getTree` | 无 | 文章树 |
| `directories.create` | 父目录相对路径、名称 | 新目录节点 |
| `directories.rename` | 目录相对路径、新名称 | 新旧路径和名称 |
| `directories.delete` | 目录相对路径 | 被删除的路径 |
| `articles.create` | 目录相对路径、名称、初始内容 | 新文章节点 |
| `articles.read` | 文章相对路径 | 路径和内容 |
| `articles.getStatus` | 文章相对路径 | 路径和修改时间 |
| `articles.save` | 文章相对路径、内容 | 路径和修改时间 |
| `articles.rename` | 文章相对路径、新名称 | 新旧路径、名称和修改时间 |
| `articles.delete` | 文章相对路径 | 被删除的路径 |

每个 IPC 处理器都校验参数类型和当前文章库状态。错误统一转换成包含错误代码和中文消息的普通对象，渲染进程不接收主进程堆栈或原始系统错误。

### 渲染进程

React 界面继续负责编辑、预览、目录树和用户提示。现有 `requestJson` 调用层替换为桌面 API 适配层，让大部分业务状态和组件逻辑保持不变。

欢迎页负责首次打开目录以及上次目录失效后的恢复。文章库已打开时，窗口使用现有三栏工作区。系统菜单提供“打开文件夹”和“打开最近使用的目录”。

## 启动和目录切换

应用启动后读取配置。上次目录存在且可访问时，主进程直接打开该目录，渲染进程加载文章树和这个文章库上次选中的文章。上次目录不存在、被移动或无权访问时，应用进入欢迎页并显示具体错误。

首次启动没有上次目录，直接显示欢迎页。用户通过原生目录选择器选择目录，主进程验证成功后更新配置并加载文章树。

切换文章库时，渲染进程先保存当前文章。保存失败则停止切换并保留当前工作区。保存成功后，主进程切换文章存储根目录，更新上次目录和最近目录，再返回新目录树。

## 编辑和保存

编辑停止 900 毫秒后自动保存，沿用当前去抖时间。切换文章、切换目录和关闭窗口前都要等待当前保存完成。

磁盘变更检测继续使用当前每 2.5 秒查询文章修改时间的方式，只把 HTTP 请求替换为 IPC。没有本地修改时，外部更新自动重新载入并提示；存在本地修改或正在保存时，继续显示冲突提示，由用户选择重新载入磁盘内容或保留当前编辑内容。

关闭窗口时，主进程先阻止默认关闭并请求渲染进程提交未保存内容。保存成功或没有修改时关闭窗口。最终保存失败时显示“继续编辑”和“放弃修改并退出”，不静默丢弃内容。

## 错误处理

- 目录不存在或无权访问：进入欢迎页并显示可操作的错误提示。
- 最近目录失效：从最近列表移除，不影响其他记录。
- 文件在读取前被删除：刷新文章树，清除失效选中项并提示。
- 保存失败：保留编辑内容，状态显示为保存失败，阻止文章或目录切换。
- 外部修改冲突：不自动覆盖本地内容，由用户选择处理方式。
- 配置文件损坏：忽略损坏内容并使用空配置启动。
- IPC 参数或路径不合法：主进程拒绝操作，返回可显示的中文错误。

## 项目结构

迁移期间保留现有 `web/` 目录，新增 `electron/` 存放桌面端代码。根目录使用统一的 `package.json` 和锁文件管理 React、Vite、Electron 与 Electron Forge。

```text
md2wechat/
├─ electron/
│  ├─ main/
│  │  ├─ main.ts
│  │  ├─ articleStore.ts
│  │  ├─ configStore.ts
│  │  └─ ipc.ts
│  ├─ preload/
│  │  └─ preload.ts
│  └─ shared/
│     └─ types.ts
├─ web/                       # 现有 React Renderer
├─ forge.config.ts
├─ package.json
└─ package-lock.json
```

实现涉及超过 8 个文件，包括依赖配置、Electron 入口、IPC、文章存储、React 调用层、欢迎页、样式、构建命令和 README。这些改动都属于桌面迁移，不顺带重构 Markdown 渲染、主题或复制模块。

## 构建和分发

开发命令同时启动 Vite 和 Electron。生产构建先生成渲染进程静态资源，再由 Electron Forge 打包当前宿主系统的应用。

Forge 配置覆盖 Windows、macOS 和 Linux。跨平台产物在对应系统的构建环境中生成。第一阶段只配置本地构建，不新增 GitHub Actions 发布流程；多平台自动构建在桌面版功能验收后单独处理。实现阶段以当前开发平台的启动、打包和功能检查作为完成门槛，开始对外发布前再完成三个系统的安装包启动检查。

第一阶段不配置签名和公证。个人使用时可以手动允许未签名应用运行；开始公开分发前，需要分别补齐 Windows 签名和 macOS 签名、公证。

新增 Electron 和 Electron Forge 依赖前需要再次确认，得到确认后才执行 `npm install`。统一根目录依赖时需要移动现有 `web/package.json` 和 `web/package-lock.json`，实施前也要按仓库规则单独确认文件移除。本设计不需要 API 密钥、第三方账号或运行中的外部服务。

## 验证

按项目规则不主动新增自动化测试。实现完成后运行现有前端测试、类型检查、lint 和生产构建，并手动检查下面的路径：

- 首次启动选择目录，重启后自动恢复。
- 上次目录不存在、被移动或没有权限时回到欢迎页。
- 任意深度目录的展示、创建、重命名和删除。
- 文章创建、读取、自动保存、重命名和删除。
- 切换文章、切换目录和关闭窗口前保存。
- 保存失败时不切换，关闭失败时允许继续编辑或放弃退出。
- 外部修改后的自动重新载入和冲突处理。
- 富文本复制到微信公众号编辑器后的排版结果。
- 关闭窗口后应用进程退出。
- 当前开发平台能启动开发版并生成可运行安装包。
- 对外发布前，Windows、macOS 和 Linux 构建分别在对应系统启动。

## 迁移和回滚

Electron 版本实现和验收期间，Go 源码、Makefile 以及当前发布工具继续保留。迁移不修改现有文章文件格式，用户选择的目录仍是普通目录和 `.md` 文件，因此可以随时回到当前 Go 版本。

Electron 版本通过功能验收后，再单独确认是否删除 Go 服务、Go 发布工具和旧构建命令。删除不属于本设计文档提交，也不会在未经确认时执行。
